# 🍕 Plato's Pizza — Business Analytics Course & Capstone Project

A complete, project-based data analytics course built around one real
dataset: a year of pizza sales. You play the role of a newly hired
analyst answering a real sequence of business requests — from "get this
data into a database" all the way to "build us a dashboard" — using
Docker, PostgreSQL, SQL, Python, pandas, and Streamlit.

**Start here:** [`docs/course-roadmap.md`](docs/course-roadmap.md) for the
full curriculum, [`docs/student-guide.md`](docs/student-guide.md) if
you're taking the course, [`docs/instructor-guide.md`](docs/instructor-guide.md)
if you're teaching it.

## Project objective

Plato's Pizza has one year (2015) of raw sales data and no analytics
infrastructure. This project takes that single CSV all the way to a
live, interactive executive dashboard — building a real database, a
sequenced SQL curriculum, a Python analysis pipeline, and a Streamlit app
along the way. Every module is framed as a business request; see
[`docs/course-roadmap.md`](docs/course-roadmap.md) for the full narrative.

## Dataset

`data/raw/pizza_sales.csv` — 48,620 rows, one row per pizza sold within an
order, covering Jan 1 – Dec 31, 2015. No separate data dictionary shipped
with the source file — the full, verified data dictionary (columns, data
quality findings, normalization decisions, and known limitations) lives in
[`data/README.md`](data/README.md). Read it before anything else; every
downstream module depends on the decisions documented there.

## Architecture

```
data/raw/pizza_sales.csv
        │
        ▼
 src/load_data.py  ──►  PostgreSQL (Docker)   [4 normalized tables]
        │                     │
        │                     ▼
        │              sql/02_*.sql … sql/08_*.sql   (SQL curriculum)
        │                     │
        │                     ▼
        └────────────►  src/extract_data.py  ──►  pandas
                              │
                              ▼
                  notebooks/01_*.ipynb … 04_*.ipynb
                  (data quality → cleaning → EDA → business analysis)
                              │
                              ▼
                  reports/insights.md   +   dashboard/app.py (Streamlit)
```

- **Database logic** (`src/load_data.py`, `src/extract_data.py`,
  `sql/01_schema.sql`): the only place the schema and JOIN patterns are
  defined. Everything downstream reuses them instead of re-deriving them.
- **Transformation logic** (`src/clean_data.py`, `src/utils.py`): cleaning,
  date-parsing, feature engineering, and the shared chart color system —
  used identically by every notebook and the dashboard.
- **Presentation logic** (`notebooks/`, `dashboard/`): consumes the above,
  never redefines it.

## Technologies

PostgreSQL 16 (Docker) · Python 3.11 · pandas / NumPy · SQLAlchemy /
psycopg2 · matplotlib / seaborn · Jupyter · Streamlit. No unnecessary
additions to the stack — see Rule 5 in the course design notes
(`docs/course-roadmap.md`): every technology here has a specific,
justified reason to exist in a beginner-to-intermediate analytics course.

## Setup

```bash
git clone <this-repo-url>
cd data-analytics

docker compose up -d              # starts PostgreSQL
cp .env.example .env              # first time only — never commit .env
pip install -r requirements.txt

python src/load_data.py           # creates schema, loads & validates data
```

Verify the load:

```bash
psql "postgresql://pizza_admin:pizza_pw@localhost:5432/pizza_analytics" \
     -f sql/02_data_quality.sql
```

Explore the SQL curriculum:

```bash
psql "postgresql://pizza_admin:pizza_pw@localhost:5432/pizza_analytics" \
     -f sql/03_basic_queries.sql
```

Run the notebooks:

```bash
jupyter lab notebooks/
```

Run the dashboard:

```bash
streamlit run dashboard/app.py
```

If the database isn't running, the dashboard automatically falls back to
`data/processed/pizza_sales_clean.csv` (generated by `python
src/clean_data.py`) with a visible warning banner — so it's always
demoable, even without Docker.

## Key findings (full report: `reports/insights.md`)

- **$817,860.05** total 2015 revenue across **21,350 orders** (49,574
  pizzas sold, avg order value **$38.31**).
- Revenue is **not concentrated**: the top 5 of 32 flavors generate only
  24.5% of revenue.
- **Popular ≠ high-value**: the top-selling flavors (Pepperoni, Hawaiian,
  Big Meat) are also the cheapest — volume drivers, not necessarily
  margin drivers (this dataset has no cost data, so margin is unknowable).
- Demand has a clear double peak: **lunch (12:00-13:00)** and **dinner
  (18:00-19:00)**.
- The clearest anomaly in the dataset: a two-day **Thanksgiving-week
  spike** (2015-11-26/27), independently confirmed in both SQL (window
  functions) and Python (rolling average).

## Limitations

No customer ID, no order channel, no cost/margin data, single location,
single year. Full discussion in [`data/README.md`](data/README.md) and
[`reports/insights.md`](reports/insights.md).
